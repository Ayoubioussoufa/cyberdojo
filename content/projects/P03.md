A script does a job once, on your machine. A tool works for someone else, handles bad input, has tests, and doesn't leak secrets. In this project you build the second kind. All the Python on this page has been run and its tests pass, so if yours fails, the difference is the clue.

@term test = Code that checks that other code does what it should.
@term continuous integration (CI) = A service that runs your tests automatically on every change.

## Step 2: Build the log parser

Your first tool turns an SSH log into records, then reports sources with many failed logins, and whether any of them then got in. Create `toolkit/logparse.py`:

```python
"""Turn an SSH auth log into records, and report likely password guessing."""
import argparse
import json
import re
import sys
from collections import Counter

FAILED = re.compile(r"Failed password for (?:invalid user )?(?P<user>\S+) from (?P<ip>\S+)")
ACCEPTED = re.compile(r"Accepted \S+ for (?P<user>\S+) from (?P<ip>\S+)")


def parse_line(line):
    """Return a record for a login line, or None for anything else."""
    for outcome, pattern in (("failed", FAILED), ("accepted", ACCEPTED)):
        match = pattern.search(line)
        if match:
            return {"outcome": outcome, "user": match["user"], "ip": match["ip"]}
    return None


def summarise(records, threshold=5):
    """Find sources with many failures, and whether any of them then got in."""
    failures = Counter(r["ip"] for r in records if r["outcome"] == "failed")
    accepted = {r["ip"] for r in records if r["outcome"] == "accepted"}
    suspects = [
        {"ip": ip, "failures": n, "got_in": ip in accepted}
        for ip, n in failures.most_common()
        if n >= threshold
    ]
    return {"total": len(records), "suspects": suspects}


def main(argv=None):
    parser = argparse.ArgumentParser(description="Summarise an SSH auth log.")
    parser.add_argument("logfile", help="path to auth.log")
    parser.add_argument("--threshold", type=int, default=5, help="failures that count as suspicious")
    parser.add_argument("--json", action="store_true", help="print JSON for other tools")
    args = parser.parse_args(argv)

    try:
        with open(args.logfile, encoding="utf-8", errors="replace") as handle:
            records = [r for r in map(parse_line, handle) if r]
    except OSError as error:
        print(f"logparse: {error}", file=sys.stderr)
        return 2

    result = summarise(records, args.threshold)
    if args.json:
        print(json.dumps(result, indent=2))
    else:
        print(f"{result['total']} login records")
        for s in result["suspects"]:
            flag = "  <-- GOT IN" if s["got_in"] else ""
            print(f"{s['ip']}: {s['failures']} failures{flag}")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

Read it slowly. Three functions do three jobs: one line, a summary, and the command line. That split is what makes it possible to test.

## Step 3: Test it

@help pytest guided

**pytest** runs functions whose names start with `test_`, and reports which ones failed. A silent parsing bug is worse than no tool, because you'd trust its wrong answer. Create `tests/test_logparse.py`:

```python
from toolkit.logparse import main, parse_line, summarise


def test_failed_login_is_parsed():
    line = "Oct 27 09:01:11 web1 sshd[811]: Failed password for root from 203.0.113.7 port 44210 ssh2"
    assert parse_line(line) == {"outcome": "failed", "user": "root", "ip": "203.0.113.7"}


def test_invalid_user_keeps_the_name():
    line = "Failed password for invalid user test from 203.0.113.7 port 44213 ssh2"
    assert parse_line(line)["user"] == "test"


def test_other_lines_are_ignored():
    assert parse_line("Started Session 42 of User ana.") is None


def test_a_success_after_failures_is_flagged():
    records = [{"outcome": "failed", "user": "root", "ip": "203.0.113.7"}] * 5
    records.append({"outcome": "accepted", "user": "deploy", "ip": "203.0.113.7"})
    assert summarise(records)["suspects"] == [{"ip": "203.0.113.7", "failures": 5, "got_in": True}]


def test_a_few_typos_are_not_suspicious():
    records = [{"outcome": "failed", "user": "ana", "ip": "10.0.0.5"}]
    assert summarise(records)["suspects"] == []


def test_the_sample_log_end_to_end(capsys):
    assert main(["samples/auth.log", "--json"]) == 0
    assert '"got_in": true' in capsys.readouterr().out


def test_a_missing_file_fails_cleanly(capsys):
    assert main(["nothere.log"]) == 2
    assert "logparse:" in capsys.readouterr().err
```

Then run:

```bash
python3 -m pytest
```

Now break your code on purpose: change `n >= threshold` to `n > threshold`, and run the tests again. One should fail. Change it back. That's how you know that a test really tests something.

## Step 4: Build the enricher, with no secrets in code

An **API** lets your program ask another service a question. You met them in [lesson 28](/courses/0028-apis-and-secrets/). Sign up for a free key at [AbuseIPDB](https://www.abuseipdb.com/), which tells you if an address has been reported.

@help api-keys guided

A key is a password. **Never put it in your code.** Keep it in `.env`, which `.gitignore` already blocks:

```bash
echo 'export ABUSEIPDB_KEY="paste-your-key-here"' > .env
source .env
```

Create `toolkit/enrich.py`. The cache means that you don't spend your daily limit asking the same question twice.

```python
"""Look up IP reputation, with a cache so that you don't waste your daily limit."""
import argparse
import json
import os
import sys
import time
from pathlib import Path

import requests

URL = "https://api.abuseipdb.com/api/v2/check"
CACHE = Path(".cache/enrich.json")
MAX_AGE = 24 * 3600


def load_cache(path=CACHE):
    return json.loads(path.read_text()) if path.exists() else {}


def save_cache(cache, path=CACHE):
    path.parent.mkdir(exist_ok=True)
    path.write_text(json.dumps(cache))


def lookup(ip, key, cache, now=None, get=requests.get):
    """Return the abuse score for an IP, from the cache if it's fresh."""
    now = now or time.time()
    hit = cache.get(ip)
    if hit and now - hit["when"] < MAX_AGE:
        return hit["score"]
    reply = get(URL, headers={"Key": key, "Accept": "application/json"}, params={"ipAddress": ip}, timeout=10)
    reply.raise_for_status()
    score = reply.json()["data"]["abuseConfidenceScore"]
    cache[ip] = {"score": score, "when": now}
    return score


def main(argv=None):
    parser = argparse.ArgumentParser(description="Check IPs against AbuseIPDB.")
    parser.add_argument("ips", nargs="+")
    args = parser.parse_args(argv)
    key = os.environ.get("ABUSEIPDB_KEY")
    if not key:
        print("enrich: set ABUSEIPDB_KEY first", file=sys.stderr)
        return 2
    cache = load_cache()
    for ip in args.ips:
        print(ip, lookup(ip, key, cache))
    save_cache(cache)
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

Look at `get=requests.get`. It lets a test pass in a fake, so tests never use the network or your key. Add `tests/test_enrich.py`:

```python
from toolkit.enrich import lookup


class FakeReply:
    def raise_for_status(self):
        pass

    def json(self):
        return {"data": {"abuseConfidenceScore": 88}}


def test_a_lookup_saves_to_the_cache():
    cache = {}
    assert lookup("203.0.113.7", "k", cache, now=1000, get=lambda *a, **k: FakeReply()) == 88
    assert cache["203.0.113.7"]["score"] == 88


def test_a_fresh_cache_makes_no_network_call():
    def explode(*a, **k):
        raise AssertionError("the network was used")

    cache = {"203.0.113.7": {"score": 5, "when": 1000}}
    assert lookup("203.0.113.7", "k", cache, now=2000, get=explode) == 5
```

Run the tests, then try it for real with `python3 -m toolkit.enrich 8.8.8.8`.

@done The enricher works, its tests pass, and `git status` doesn't list `.env`.

## Step 5: Put it in a container

@help docker guided

A **container** packages a program with everything it needs, so that it runs the same anywhere. You met containers in [lesson 29](/courses/0029-tests-and-docker/). Install Docker by following [the official guide](https://docs.docker.com/engine/install/ubuntu/), and check it with `docker run hello-world`.

An **image** is the recipe's result, and a **container** is a running copy of it. Create a `Dockerfile`:

```dockerfile
FROM python:3.13-slim
RUN useradd --create-home app
WORKDIR /home/app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY toolkit toolkit
USER app
ENTRYPOINT ["python", "-m", "toolkit.logparse"]
```

Line by line: start from a small Python image, make a normal user, install your packages, copy your code, then drop root. Running as a normal user limits the damage if your tool is ever attacked. Build and run:

```bash
docker build -t toolkit .
docker run --rm -v "$PWD/samples:/data:ro" toolkit /data/auth.log
```

`-v` shows the container your samples folder, and `:ro` makes it read-only.

@done My tool runs in Docker, and it prints the same result.

## Step 6: Stop secrets before they're committed

@help gitleaks guided

**gitleaks** scans for keys and passwords. A secret that reaches GitHub is compromised, even if you delete it a minute later, because Git keeps history and bots scan constantly.

@help precommit guided

**pre-commit** runs checks automatically each time you commit. Install it, and create `.pre-commit-config.yaml`:

```bash
python3 -m pip install pre-commit
```

```yaml
repos:
  - repo: https://github.com/gitleaks/gitleaks
    rev: v8.30.1
    hooks:
      - id: gitleaks
```

Check [gitleaks' releases](https://github.com/gitleaks/gitleaks/releases) for the newest version, then switch it on:

```bash
pre-commit install
pre-commit run --all-files
```

## Step 7: Run your tests on every push

@help github-actions guided

**GitHub Actions** runs your commands on GitHub's computers whenever you push. Create `.github/workflows/tests.yml`:

```yaml
name: tests
on: [push, pull_request]
permissions:
  contents: read
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-python@v6
        with:
          python-version: "3.13"
      - run: pip install -r requirements.txt
      - run: python -m pytest
```

`permissions: contents: read` gives the job the least it needs. Push, then open the **Actions** tab on GitHub, and watch it run. A green tick means that your tests passed on a clean machine, which is stronger proof than "it works on my laptop".

@done The Actions tab shows a green tick.

## Step 8: Add a Windows tool, and finish

@help powershell guided

You'll need the PowerShell from [lesson 34](/courses/0034-powershell/), so do this step in Month 5. On a Windows VM, this script collects a quick picture of the machine. It only reads. Save it as `wintriage.ps1`, and run it in an administrator PowerShell window.

```powershell
# wintriage.ps1: a quick, read-only picture of a Windows machine, as JSON.
$report = [ordered]@{
  host      = $env:COMPUTERNAME
  time      = (Get-Date).ToUniversalTime().ToString("o")
  processes = Get-CimInstance Win32_Process | Select-Object ProcessId, ParentProcessId, Name, CommandLine
  services  = Get-CimInstance Win32_Service | Where-Object StartMode -eq "Auto" | Select-Object Name, State, PathName
  tasks     = Get-ScheduledTask | Where-Object State -ne "Disabled" | Select-Object TaskName, TaskPath, State
  listening = Get-NetTCPConnection -State Listen | Select-Object LocalAddress, LocalPort, OwningProcess
}
$report | ConvertTo-Json -Depth 4 | Out-File -Encoding utf8 triage.json
```
