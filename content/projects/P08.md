## Step 2: Write your first Sigma rule

@goal Install `sigma-cli` with the Splunk plugin, and write a rule at `rules/windows/office_spawns_shell.yml` for Word or Excel starting a shell. It must pass `sigma check` and convert to a Splunk query.
@search sigma rule specification | sigma-cli convert splunk | sigma process creation logsource

@help sigma guided

**Sigma** is a shared format for detection rules, which you read in [lesson 58](/courses/0058-detection-engineering/). Install its tool:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install sigma-cli
sigma plugin install splunk
sigma plugin install sysmon
```

Create `rules/windows/office_spawns_shell.yml`:

```yaml
title: Office Application Spawning a Shell
id: 3e1f8a52-7c1d-4f6e-9a2b-5d0c7e4b1a11
status: experimental
description: Word or Excel started a command shell.
author: Your Name
date: 2026-11-06
logsource:
  product: windows
  category: process_creation
detection:
  selection:
    ParentImage|endswith:
      - '\WINWORD.EXE'
      - '\EXCEL.EXE'
    Image|endswith:
      - '\cmd.exe'
      - '\powershell.exe'
  condition: selection
falsepositives:
  - Some legitimate add-ins
level: high
tags:
  - attack.execution
  - attack.t1059.001
```

Generate a fresh `id` for each rule with `python3 -c "import uuid; print(uuid.uuid4())"`. Check the rule, then convert it:

```bash
sigma check rules
sigma convert -t splunk -p sysmon -p splunk_windows rules
```

You should see `No rule errors found`, and then a Splunk query. Conversion proves the logic is portable, even if you don't use Splunk. Run `sigma plugin list` to see other backends. Some plugins lag behind new versions of Sigma, so if one says it isn't compatible, Splunk's is a safe choice for your checks. For Wazuh, translate the logic by hand into a rule like the one in P06.

@done `sigma check` passes, and my rule converts.

## Step 3: Run a safe test

@goal On a `ws1` snapshot, install Invoke-AtomicRedTeam, read a test for T1059.001 before running it, then run it, clean up, and find what it left in your logs. Stay on your lab network.
@search invoke-atomicredteam install | t1059.001 powershell technique

@help atomic guided

**Atomic Red Team** is a library of small tests, each one doing a single technique. On a `ws1` snapshot, in PowerShell:

```powershell
Install-Module -Name invoke-atomicredteam,powershell-yaml -Scope CurrentUser
Import-Module invoke-atomicredteam
```

See what's available, and read a test **before** you run it:

```powershell
Invoke-AtomicTest T1059.001 -ShowDetailsBrief
Invoke-AtomicTest T1059.001 -TestNumbers 1 -ShowDetails
```

Then get what it needs, run it, and clean up:

```powershell
Invoke-AtomicTest T1059.001 -TestNumbers 1 -GetPrereqs
Invoke-AtomicTest T1059.001 -TestNumbers 1
Invoke-AtomicTest T1059.001 -TestNumbers 1 -Cleanup
```

::: law Lab machines only
These tests really do what they say, and they can leave a system in a bad state. Use a snapshot, and stay on your lab network. Some need antivirus to be off, so read each one first.
:::

@reveal Show me the workflow
```yaml

on: [push, pull_request]
permissions:
  contents: read
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-python@v6

          python-version: "3.13"
      - run: pip install sigma-cli
```

## Step 7: Respond to an intrusion

@goal Set up a Velociraptor server and add `ws1`. Have a friend or a script carry out a small simulated intrusion using techniques you've tested, respond to it, collect evidence, and write an incident report.
@search velociraptor quickstart | velociraptor artifact collection | incident report template nist

@help velociraptor guided

**Velociraptor** collects evidence from many machines at once. Follow [its quickstart](https://docs.velociraptor.app/docs/deployment/quickstart/), downloading the latest Linux release to a new VM, then:

```bash
chmod +x velociraptor
./velociraptor config generate -i
./velociraptor debian server --config ./server.config.yaml
sudo dpkg -i velociraptor_server_*.deb
```

The wizard asks for a few choices, and it creates your admin user. The interface is at `https://127.0.0.1:8889`. To add `ws1`, go to **Server Artifacts** in the interface, run `Server.Utils.CreateMSI`, and install the MSI that it produces.

Have a friend or a script carry out a small simulated intrusion on `ws1`, using techniques that you've tested. Respond as in [lesson 59](/courses/0059-incident-response/), collect evidence with Velociraptor, and write the full report: timeline in UTC, scope, root cause, containment, recovery and lessons.
