**Wazuh** is a free security platform that collects logs, raises alerts and has a dashboard. Create an Ubuntu Server **24.04** VM, called `siem1`, at `192.168.1.30` on `lab-lan`, with 4 CPUs, 8 GB of memory and 50 GB of disk. Check [the quickstart](https://documentation.wazuh.com/current/quickstart.html) for supported versions before you pick one. Then run the installer:

```bash
curl -sO https://packages.wazuh.com/4.14/wazuh-install.sh && sudo bash ./wazuh-install.sh -a
```

`-a` installs all the parts on one machine. It takes a while, and then prints a password. Save it. If you lose it:

```bash
sudo tar -O -xvf wazuh-install-files.tar wazuh-install-files/wazuh-passwords.txt
```

From Kali, open `https://192.168.1.30`, accept the certificate warning, and log in as `admin`.

## Step 3: Connect your machines

@goal Install Wazuh agents on `srv1`, `ws1` and `dc1`. `srv1` sits in the DMZ, so allow it through the firewall to `192.168.1.30` on TCP ports 1514 and 1515.
@search wazuh agent install linux | wazuh agent ports 1514 1515

An **agent** on each machine forwards its logs. Wazuh's documentation also shows these commands in the dashboard, under **Deploy new agent**.

On `srv1`:

```bash
sudo apt-get install gnupg apt-transport-https curl
curl -s https://packages.wazuh.com/key/GPG-KEY-WAZUH | sudo gpg --no-default-keyring --keyring gnupg-ring:/usr/share/keyrings/wazuh.gpg --import && sudo chmod 644 /usr/share/keyrings/wazuh.gpg
echo "deb [signed-by=/usr/share/keyrings/wazuh.gpg] https://packages.wazuh.com/4.x/apt/ stable main" | sudo tee -a /etc/apt/sources.list.d/wazuh.list
sudo apt-get update
sudo WAZUH_MANAGER="192.168.1.30" apt-get install wazuh-agent
sudo systemctl daemon-reload
sudo systemctl enable --now wazuh-agent
```

Remember your firewall: `srv1` is in the DMZ, so you'll need to allow it to reach `192.168.1.30` on TCP ports 1514 and 1515.

On `ws1` and `dc1`, download the agent from [the Windows install page](https://documentation.wazuh.com/current/installation-guide/wazuh-agent/wazuh-agent-package-windows.html). Then, in an administrator PowerShell window, in the download folder:

```powershell
msiexec.exe /i .\wazuh-agent-4.14.10-1.msi /q WAZUH_MANAGER="192.168.1.30"
Start-Service wazuhsvc
```

Use the file name that you actually downloaded.

## Step 4: Send Sysmon to the SIEM

@goal Confirm that Sysmon still runs on `ws1`, then make its agent collect the Sysmon log. Your process events should appear in Wazuh with their fields parsed.
@search wazuh collect sysmon logs eventchannel | wazuh ossec.conf localfile

@help sysmon recall

**Your task:** confirm that Sysmon is still running on `ws1`, from P04, and that you can find event 1 in its log.

@reveal Show me how
```powershell
Get-Service Sysmon64
Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" -MaxEvents 3
```
@endreveal

Wazuh doesn't read that log by default. On `ws1`, edit `C:\Program Files (x86)\ossec-agent\ossec.conf` as Administrator, and add this inside `<ossec_config>`:

```xml
<localfile>
  <location>Microsoft-Windows-Sysmon/Operational</location>
  <log_format>eventchannel</log_format>
</localfile>
```

Restart the agent with `Restart-Service wazuhsvc`, then open Notepad. In the dashboard, search for that event. Check that its fields, such as the parent image, have been parsed. A log that arrives unparsed can't be searched properly.

## Step 5: Watch Linux with auditd

@goal Use auditd on `srv1` to watch sensitive files such as `/etc/passwd`, `/etc/sudoers` and `/etc/crontab`, then send its log to Wazuh. A change to a watched file should show up there.
@search auditd rules watch file | ausearch key | wazuh monitor audit log
@docs audit.rules | https://man7.org/linux/man-pages/man7/audit.rules.7.html

@help auditd guided

**auditd** records security events from the Linux kernel, such as who changed a file. On `srv1`:

```bash
sudo apt install auditd
sudo tee /etc/audit/rules.d/lab.rules <<'EOF'
-w /etc/passwd -p wa -k identity
-w /etc/sudoers -p wa -k identity
-w /etc/crontab -p wa -k persistence
EOF
sudo augenrules --load
sudo auditctl -l
```

`-w` watches a file, `-p wa` means writes and attribute changes, and `-k` adds a label for searching. Test it by touching a watched file, then searching:

```bash
sudo touch /etc/crontab
sudo ausearch -k persistence
```

Now send it to Wazuh. Add this to `/var/ossec/etc/ossec.conf` on `srv1`, then restart with `sudo systemctl restart wazuh-agent`:

```xml
<localfile>
  <log_format>audit</log_format>
  <location>/var/log/audit/audit.log</location>
</localfile>
```

@done A change to a watched file on `srv1` shows up in Wazuh.

## Step 6: Add the firewall

@goal Send OPNsense's logs to `siem1` on UDP port 514, generate blocked traffic, and confirm that it arrives and is parsed.
@search opnsense remote syslog | wazuh syslog remote listener
@docs Wazuh syslog collection | https://documentation.wazuh.com/current/cloud-service/your-environment/send-syslog-data.html

Your third source. In OPNsense, go to **System → Settings → Logging**, and add a remote log target pointing at `192.168.1.30`, UDP port 514. On `siem1`, add this to `/var/ossec/etc/ossec.conf`, then run `sudo systemctl restart wazuh-manager`:

```xml
<remote>
  <connection>syslog</connection>
  <port>514</port>
  <protocol>udp</protocol>
  <allowed-ips>192.168.1.1</allowed-ips>
</remote>
```

Generate blocked traffic, and confirm that it arrives. You've now met the gate's three log sources.

@done Firewall logs reach Wazuh, and their parsing works.

## Step 7: Write ten detections

@goal Write ten custom Wazuh rules in `local_rules.xml` for behaviour you can really trigger, and test them with `wazuh-logtest`. Record each with its technique, data source, logic, test result and false-positive notes.
@search wazuh custom rules | wazuh-logtest | mitre attack techniques list
@docs Wazuh rules syntax | https://documentation.wazuh.com/current/user-manual/ruleset/ruleset-xml-syntax/rules.html
@docs MITRE ATT&CK | https://attack.mitre.org/

Custom rules live in `/var/ossec/etc/rules/local_rules.xml` on `siem1`. Here's one, written from the idea in [lesson 58](/courses/0058-detection-engineering/):

```xml
<group name="local,sysmon,">
  <rule id="100100" level="12">
    <if_group>sysmon_event1</if_group>
    <field name="win.eventdata.parentImage" type="pcre2">(?i)\\(winword|excel)\.exe$</field>
    <field name="win.eventdata.image" type="pcre2">(?i)\\(cmd|powershell)\.exe$</field>
    <description>Office application started a shell</description>
    <mitre>
      <id>T1059</id>
    </mitre>
  </rule>
</group>
```

Test a rule with `sudo /var/ossec/bin/wazuh-logtest`, by pasting in a sample event. Then restart with `sudo systemctl restart wazuh-manager`.

Pick nine more that you can really trigger. Some ideas:

| Behaviour | Log |
|---|---|
| Many failed logons from one source | Windows Security |
| New service installed (7045) | Windows System |
| New local admin (4732) | Windows Security |
| Encoded PowerShell | Sysmon |
| Security log cleared (1102) | Windows Security |
| `/etc/passwd` changed | auditd |
| SSH success after failures | auth.log |

Record each one in a table: technique, data source, logic, test result, and false-positive notes.

@done I have ten rules, each with an ATT&CK technique.
