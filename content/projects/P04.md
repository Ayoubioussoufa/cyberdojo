Most companies run on Windows and Active Directory. Here you build a small one that you control completely, and that you can rebuild from scripts. Your SOC, your penetration test and your detections will all run against this lab.

The PowerShell on this page has been checked for correct syntax, but it couldn't be run here against a real domain, so read any error carefully. The commands follow [Microsoft's AD DS guide](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/deploy/install-active-directory-domain-services--level-100-).

@term domain controller = The server that holds a domain's accounts and answers logons.
@term organisational unit (OU) = A folder in Active Directory for grouping users and computers.
@term Group Policy Object (GPO) = A set of settings pushed to many machines at once.

## Step 2: Install Windows Server

@help virtualbox recall

**Your task:** create two VMs. Download the evaluation versions of Windows Server and Windows 11 Enterprise from Microsoft's [Evaluation Center](https://www.microsoft.com/en-us/evalcenter). They're free for lab use. Give `dc1` 2 CPUs, 4 GB of memory and a 60 GB disk, and `ws1` 2 CPUs, 4 GB and 60 GB. Attach both to `lab-lan`. Windows 11 needs EFI and TPM turned on in the VM's settings.

@reveal Show me the VirtualBox steps
Click **New**, pick the ISO, and set the memory and disk as above. Open **Settings → Network**, set the adapter to **Internal Network**, and choose `lab-lan` from the list. Under **Settings → System**, tick **Enable EFI** and set the TPM to v2.0 for `ws1`. Take a snapshot as soon as Windows is installed.
@endreveal

@help windows-server guided

Install Windows Server on `dc1`, and pick the version **with Desktop Experience**, so that you get the normal screen. Choose an Administrator password and store it in your password manager.

Sign in, and open PowerShell as Administrator. This gives the server a fixed address and its name. Save it as `01-prepare.ps1` in your repository, then run it.

```powershell
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.1.10 -PrefixLength 24 -DefaultGateway 192.168.1.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 127.0.0.1
Rename-Computer -NewName dc1 -Restart
```

A domain controller also runs DNS for the domain, which is why it points to itself.

@done `dc1` has its fixed address and its name.

## Step 3: Create the domain

@help active-directory guided

This turns an ordinary server into a domain controller. Save it as `02-forest.ps1`, and run it as Administrator.

```powershell
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools
Install-ADDSForest -DomainName "corp.oasis.example"
```

The first line installs the role. The second creates a new **forest**, the top level of Active Directory. It asks for a recovery password, and then it restarts. Afterwards, sign in as `CORP\Administrator`, and check:

```powershell
Get-ADDomain | Select-Object DNSRoot, NetBIOSName, DomainMode
```

Take a snapshot called `dc-fresh`.

@done `Get-ADDomain` shows `corp.oasis.example`.

## Step 4: Add people, by script

@help powershell recall

**Your task:** write `03-populate.ps1`. It should create an OU and a group for each department, then 5 users in each, added to that department's group. Clicking through menus can't be rebuilt, and a script can. Try it first, using `Get-Help New-ADUser -Examples`.

@reveal Show me the script
```powershell
Import-Module ActiveDirectory
$domain = (Get-ADDomain).DistinguishedName
$password = Read-Host -AsSecureString "Password for the lab users"
foreach ($dept in "Finance", "HR", "IT", "Sales") {
  New-ADOrganizationalUnit -Name $dept -Path $domain
  New-ADGroup -Name "$dept-Staff" -GroupScope Global -Path "OU=$dept,$domain"
  foreach ($n in 1..5) {
    $sam = "$($dept.ToLower())$n"
    New-ADUser -Name $sam -SamAccountName $sam -Path "OU=$dept,$domain" -AccountPassword $password -Enabled $true
    Add-ADGroupMember -Identity "$dept-Staff" -Members $sam
  }
}
```
@endreveal

Never put a password in the script itself, which is why it asks with `Read-Host`. Check your work with `Get-ADUser -Filter * | Measure-Object`.

@done I have 20 users in 4 departments, created by my script.

## Step 5: Join the workstation

Install Windows 11 on `ws1`. In PowerShell as Administrator:

```powershell
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.1.20 -PrefixLength 24 -DefaultGateway 192.168.1.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 192.168.1.10
```

After it restarts:

```powershell
Add-Computer -DomainName corp.oasis.example -Credential CORP\Administrator -Restart
```

Sign in as `CORP\sales1`. If it can't find the domain, DNS is the usual reason, so check that `ws1` points to `192.168.1.10`.

## Step 6: Turn on the logging

@help gpo guided

A **GPO** applies settings to many machines, so that you don't have to touch each one. On `dc1`:

```powershell
$domain = (Get-ADDomain).DistinguishedName
New-GPO -Name "Audit-Baseline" | New-GPLink -Target $domain
Set-GPRegistryValue -Name "Audit-Baseline" -Key "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" -ValueName EnableScriptBlockLogging -Type DWord -Value 1
```

That last line records PowerShell scripts, which you learned about in [lesson 33](/courses/0033-windows-logging-and-sysmon/).

Some settings are easier by hand. Open **Group Policy Management**, right-click `Audit-Baseline`, and choose **Edit**. Under **Computer Configuration → Policies → Windows Settings → Security Settings → Advanced Audit Policy Configuration**, turn on success and failure for Logon, Process Creation, Kerberos Service Ticket Operations, and User Account Management. Then, under **Administrative Templates → System → Audit Process Creation**, enable **Include command line in process creation events**.

On `ws1`, run `gpupdate /force`, then `gpresult /r`, and check that `Audit-Baseline` is listed. Add two more GPOs of your own, such as a screen lock and a password policy, to reach the gate's 3 GPOs. Export them with `Backup-GPO -All -Path C:\gpo-backup`, so that they can be rebuilt.

@done Event 4688 on `ws1` shows command lines, and I have 3 GPOs.

## Step 7: Add deliberate weaknesses

A perfect lab teaches you nothing. Add realistic mistakes, and write each one down in `WEAKNESSES.md`, with why it happens in real companies.

```powershell
$domain = (Get-ADDomain).DistinguishedName
$weak = Read-Host -AsSecureString "A deliberately weak lab password"
New-ADUser -Name svc_sql -SamAccountName svc_sql -Path "OU=IT,$domain" -AccountPassword $weak -Enabled $true -PasswordNeverExpires $true
setspn -S MSSQLSvc/srv1.corp.oasis.example:1433 svc_sql
Add-ADGroupMember -Identity "Domain Admins" -Members "it1"
```

| Weakness | Why it's realistic |
|---|---|
| A service account with a weak password | Old systems, and nobody dares to change it |
| A helpdesk user in Domain Admins | "It was only meant to be temporary" |

The service account has an SPN, so it's the kind of target you met in [lesson 44](/courses/0044-kerberos-and-ntlm/). Keep this lab away from any real network, and never reuse these passwords.

@done `WEAKNESSES.md` lists each weakness with its reason.

## Step 8: Install Sysmon

@help sysmon guided

**Sysmon** records far more detail than Windows does by default, as you saw in [lesson 33](/courses/0033-windows-logging-and-sysmon/). Download it from [Microsoft Sysinternals](https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon), and download the configuration file from [SwiftOnSecurity/sysmon-config](https://github.com/SwiftOnSecurity/sysmon-config). On `ws1` and `dc1`, as Administrator, in the folder holding both:

```powershell
.\Sysmon64.exe -accepteula -i sysmonconfig-export.xml
```

Open **Event Viewer → Applications and Services Logs → Microsoft → Windows → Sysmon → Operational**. Start Notepad, then look for event ID 1. Keep the [Sysmon sheet](/sheets/sysmon-ids/) open.

@done I can find my own Notepad start in the Sysmon log.

## Step 9: Measure your starting point

@help pingcastle guided

**PingCastle** scores the health of a domain. Download it from [pingcastle.com](https://www.pingcastle.com/), unpack it on `ws1`, run `PingCastle.exe`, and pick **healthcheck** from its menu. It writes an HTML report. Copy it to your repository as your baseline.

@help bloodhound guided

**BloodHound** draws your domain as a graph, to reveal paths to admin, as in [lesson 45](/courses/0045-attacking-and-defending-identity/). On Kali, with Docker installed:

```bash
wget https://github.com/SpecterOps/bloodhound-cli/releases/latest/download/bloodhound-cli-linux-amd64.tar.gz
tar -xvzf bloodhound-cli-linux-amd64.tar.gz
./bloodhound-cli install
```

It prints a password. Log in at `http://localhost:8080/ui/login` as `admin`. Inside, download the SharpHound collector, run it on `ws1` as a domain user, and upload the ZIP it creates.

::: law
SharpHound is noisy and well known. Run it only in your own lab.
:::
