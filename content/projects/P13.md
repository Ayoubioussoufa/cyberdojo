This project handles real malware, so safety comes first, last and in the middle. Read [lesson 67](/courses/0067-safe-malware-triage/) again before you start.

::: law Non-negotiable
Never run a sample on your own computer, or on any network you care about. If you're unsure about a step, stop. Use commodity samples only. Publish hashes, never samples.
:::

@term host-only network = A virtual network that reaches only the host and other VMs, never the internet.
@term FakeNet-NG = A tool that imitates internet services, so that malware's network behaviour can be observed.

## Step 1: Build the lab

@help remnux guided

**REMnux** is a Linux toolkit for analysing malware. Download the VirtualBox file from [its docs](https://docs.remnux.org/install-distro/get-virtual-appliance), check its SHA-256 against the page, and import it. The login is `remnux` / `malware`. While it's still online, update it with `remnux install`, then take a snapshot.

@help flare-vm guided

**FLARE-VM** turns a Windows VM into an analysis machine. It needs a Windows 10 or later VM, with 60 GB of disk and no spaces in the username, and you must turn off Defender and updates **in that VM only**. In PowerShell as Administrator:

```powershell
(New-Object net.webclient).DownloadFile('https://raw.githubusercontent.com/mandiant/flare-vm/main/install.ps1',"$([Environment]::GetFolderPath("Desktop"))\install.ps1")
Unblock-File .\install.ps1
Set-ExecutionPolicy Unrestricted -Force
.\install.ps1
```

It takes hours. Afterwards, take a snapshot.

@done Both VMs are installed, and I've taken a clean snapshot of each.

## Step 2: Isolate it, and prove it

Set both VMs to a **host-only** or internal network, with no shared folders, clipboard or drag and drop. Then prove it, before any sample comes near:

```bash
ping -c 2 8.8.8.8
curl -m 5 https://example.com
```

Both must fail. Save the output in your notes.

@done I've proved that neither VM can reach the internet.

## Step 3: Get two samples, and triage them

Download commodity samples from [MalwareBazaar](https://bazaar.abuse.ch/), and move them into the lab as password-protected ZIPs. Never unpack them outside the VM. Rename each to end in `.vir`, so that a double-click can't run it.

Start without running anything, as in [lesson 67](/courses/0067-safe-malware-triage/). Hash it, and search for the hash. Check the file type, the imports, and the entropy of each section using **PEStudio** in FLARE-VM.

@help capa guided

**capa** says what a program can do. It comes with FLARE-VM.

```powershell
capa.exe sample.vir
capa.exe sample.vir -vv
```

`-vv` shows the evidence for each claim. **FLOSS**, which also comes with FLARE-VM, finds hidden strings, as `floss.exe sample.vir`.

Write down the hashes, strings, imports and capabilities. Treat each as a clue, not a verdict.

@done I've got static findings for both samples, and I haven't run either.

## Step 4: Watch it run

Take a snapshot. Then prepare to observe.

@help fakenet guided

**FakeNet-NG**, in FLARE-VM, answers malware's network requests, so that you can see what it asks for, while nothing leaves. Start it from its shortcut, and leave it running.

@help procmon guided

**Process Monitor** records file, registry and process activity. Start it, and filter out the noise by using **Filter → Process Name**.

Now run the sample in FLARE-VM, wait a few minutes, and stop. Record what it created, changed, started and contacted, and how it survives a reboot. Then **restore your snapshot**.

@done I've recorded each sample's behaviour, and restored my clean snapshot.

## Step 5: Read one function

@help ghidra guided

**Ghidra** turns a program back into something like C. It's in FLARE-VM. Create a project, import the sample, and let it run its analysis. In the **Symbol Tree**, find an interesting import, such as a network function, then follow its references to the code that calls it.

You don't need to understand it all. Pick one function, and write what it does in plain words.

@done I can describe what one function does.

## Step 6: Write rules that work

@help yara guided

**YARA** matches files against patterns, as you saw in [lesson 67](/courses/0067-safe-malware-triage/). Write a rule from stable features, such as unusual strings, rather than things that change. Save it as `family.yar`, and test:

```bash
yara family.yar sample.vir
yara -r family.yar C:\Windows\System32
```

The first must match. The second is your clean set, and it must match **nothing**. If it fires on normal files, your rule isn't ready.

@help sigma solo

Write two Sigma rules for what the sample **does**.

@done My YARA rules match the samples and nothing in the clean set, and I've got two Sigma rules.
