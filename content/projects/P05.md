Plenty of people can name web flaws. Few can show the line that caused one, the test that proves it, and the fix. That's what you'll build here: a small notes app, written properly, then broken on purpose, on a separate branch.

Every file on this page was run before it was written here: the app, the database and the tests. If something behaves differently for you, compare it line by line.

## Step 2: Start PostgreSQL

@help postgresql guided

This is your first database, so let's go slowly.

**PostgreSQL** is a database server: a program that runs all the time, keeps your data on disk, and answers questions from other programs. You talk to it in **SQL**, which you met in [lesson 37](/courses/0037-databases-and-sql/). Data lives in **tables**: `users` might have columns `id` and `email`, with one row per person.

You don't need to install it. You'll run it in a container, so that it can be deleted cleanly.

@help docker-compose guided

**Docker Compose** starts containers from a file, so that you don't have to remember long commands. Create `compose.yaml`:

```yaml
services:
  db:
    image: postgres:18-alpine
    environment:
      POSTGRES_USER: notes
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: notes
    ports:
      - "127.0.0.1:55432:5432"
    volumes:
      - dbdata:/var/lib/postgresql

volumes:
  dbdata:
```

Here's what each part does:

| Line | Meaning |
|---|---|
| `image: postgres:18-alpine` | Which PostgreSQL to run |
| `environment` | Creates a user and a database on first start |
| `${DB_PASSWORD}` | Read from your `.env` file, so it's never in your code |
| `127.0.0.1:55432:5432` | Only your own laptop can connect, on port 55432 |
| `volumes` | Keeps your data if the container restarts |

Create `.env`, which is blocked from Git. Use long random values:

```bash
DB_PASSWORD=change-this-long-random-value
SECRET_KEY=change-this-too
```

Start it:

```bash
docker compose up -d --wait
```

`-d` runs it in the background, and `--wait` waits until it's ready. Now step inside the database with `psql`, PostgreSQL's command-line tool:

```bash
docker compose exec db psql -U notes -d notes
```

Your prompt changes to `notes=#`. You're talking to the database. Try these:

| Type this | It does |
|---|---|
| `SELECT version();` | Shows the version. SQL ends with `;` |
| `\dt` | Lists tables. There are none yet |
| `\q` | Quits |

Commands starting with a backslash belong to `psql`, and they aren't SQL.

## Step 3: Create the tables

A database needs a shape before it can hold anything. Create `schema.sql`:

```sql
CREATE TABLE IF NOT EXISTS users (
  id SERIAL PRIMARY KEY,
  email TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  is_admin BOOLEAN NOT NULL DEFAULT FALSE
);

CREATE TABLE IF NOT EXISTS notes (
  id SERIAL PRIMARY KEY,
  owner_id INTEGER NOT NULL REFERENCES users(id),
  title TEXT NOT NULL,
  body TEXT NOT NULL
);
```

Reading it: `SERIAL PRIMARY KEY` gives each row a unique number automatically. `UNIQUE` stops two accounts using one email. `REFERENCES users(id)` means that a note must belong to a real user, and the database itself enforces that. Note that there's a `password_hash` column, and no password column at all.

Load it, and look at the result:

```bash
docker compose exec -T db psql -U notes -d notes < schema.sql
docker compose exec db psql -U notes -d notes -c '\dt'
```

You should see `notes` and `users`. Make a second database for your tests, so that they can't touch your real data:

```bash
docker compose exec db createdb -U notes notes_test
```

@done `\dt` lists both tables, and `notes_test` exists.

## Step 4: Build the app

@help flask guided

**Flask** is a small Python web framework. You write a function for each web address, and Flask calls it when a request arrives. Create `app/__init__.py`:

```python
import os

import psycopg
from argon2 import PasswordHasher
from argon2.exceptions import VerifyMismatchError
from flask import Flask, abort, g, redirect, render_template, request, session, url_for

hasher = PasswordHasher()


def create_app(database_url=None):
    app = Flask(__name__)
    app.secret_key = os.environ["SECRET_KEY"]
    app.config.update(SESSION_COOKIE_HTTPONLY=True, SESSION_COOKIE_SAMESITE="Lax")
    url = database_url or os.environ["DATABASE_URL"]

    def db():
        if "db" not in g:
            g.db = psycopg.connect(url, autocommit=True)
        return g.db

    @app.teardown_appcontext
    def close_db(_error):
        conn = g.pop("db", None)
        if conn:
            conn.close()

    def current_user():
        return session.get("user_id")

    @app.get("/")
    def home():
        return redirect(url_for("list_notes"))

    @app.get("/register")
    def register_page():
        return render_template("register.html")

    @app.post("/register")
    def register():
        email = request.form["email"].strip().lower()
        password = request.form["password"]
        if len(password) < 12:
            return "Use at least 12 characters.", 400
        db().execute("INSERT INTO users (email, password_hash) VALUES (%s, %s)", (email, hasher.hash(password)))
        return redirect(url_for("login_page"))

    @app.get("/login")
    def login_page():
        return render_template("login.html")

    @app.post("/login")
    def login():
        row = db().execute("SELECT id, password_hash FROM users WHERE email = %s", (request.form["email"].strip().lower(),)).fetchone()
        try:
            if row is None:
                raise VerifyMismatchError
            hasher.verify(row[1], request.form["password"])
        except VerifyMismatchError:
            return "Wrong email or password.", 401
        session.clear()
        session["user_id"] = row[0]
        return redirect(url_for("list_notes"))

    @app.get("/notes")
    def list_notes():
        if not current_user():
            return redirect(url_for("login_page"))
        q = request.args.get("q", "")
        rows = db().execute(
            "SELECT id, title FROM notes WHERE owner_id = %s AND title ILIKE %s ORDER BY id",
            (current_user(), f"%{q}%"),
        ).fetchall()
        return render_template("notes.html", notes=rows, q=q)

    @app.post("/notes")
    def add_note():
        if not current_user():
            abort(401)
        db().execute("INSERT INTO notes (owner_id, title, body) VALUES (%s, %s, %s)", (current_user(), request.form["title"], request.form["body"]))
        return redirect(url_for("list_notes"))

    @app.get("/notes/<int:note_id>")
    def show_note(note_id):
        if not current_user():
            abort(401)
        row = db().execute("SELECT title, body FROM notes WHERE id = %s AND owner_id = %s", (note_id, current_user())).fetchone()
        if row is None:
            abort(404)
        return render_template("note.html", title=row[0], body=row[1])

    return app
```

It's long, so read one route at a time. Four security decisions are built in:

| Where | Decision | Lesson |
|---|---|---|
| `hasher.hash(password)` | Passwords are hashed with Argon2 | [40](/courses/0040-storing-passwords/) |
| `%s` with a separate tuple | Values never enter the SQL text | [47](/courses/0047-keeping-input-out-of-the-code/) |
| `AND owner_id = %s` | Only the owner finds a note | [48](/courses/0048-access-control-that-holds/) |
| `session.clear()` at login | A new session each time | [36](/courses/0036-sessions-and-the-browser/) |

Now the pages. Create `app/templates/login.html`:

`app/templates/notes.html`:

`tests/test_security.py`:

```python
from .conftest import sign_up


def test_a_password_is_never_stored_in_plain_text(client, app):
    import psycopg
    from .conftest import URL
    sign_up(client, "a@example.com")
    with psycopg.connect(URL) as conn:
        stored = conn.execute("SELECT password_hash FROM users").fetchone()[0]
    assert stored.startswith("$argon2")


def test_a_user_cannot_read_someone_elses_note(app):
    alice, bob = app.test_client(), app.test_client()
    sign_up(alice, "alice@example.com")
    sign_up(bob, "bob@example.com")
    alice.post("/notes", data={"title": "private", "body": "alice only"})
    assert alice.get("/notes/1").status_code == 200
    assert bob.get("/notes/1").status_code == 404


def test_an_apostrophe_in_a_search_is_harmless(client):
    sign_up(client, "c@example.com")
    client.post("/notes", data={"title": "O'Brien invoice", "body": "x"})
    reply = client.get("/notes", query_string={"q": "O'Brien"})
    assert reply.status_code == 200
    assert b"invoice" in reply.data


def test_html_in_a_note_is_shown_as_text(client):
    sign_up(client, "d@example.com")
    client.post("/notes", data={"title": "t", "body": "<b>hello</b>"})
    assert b"<b>hello</b>" not in client.get("/notes/1").data
    assert b"&lt;b&gt;hello" in client.get("/notes/1").data
```
@endreveal

## Step 7: Add a real access control flaw

Now you'll break it on purpose, on a separate branch, so that `main` stays safe:

```bash

```

In `show_note`, remove the ownership check, so that the line reads like a real mistake:

```python
row = db().execute("SELECT title, body FROM notes WHERE id = %s", (note_id,)).fetchone()
```

It looks fine, and it even works. Run your tests. `test_a_user_cannot_read_someone_elses_note` fails, because Bob can now read Alice's note. That's an **IDOR**, and your test has just proved it without any attack tool.

## Step 8: Add a SQL flaw, and prove it harmlessly

In `list_notes`, build the SQL as text:

```python
rows = db().execute(
    f"SELECT id, title FROM notes WHERE owner_id = {current_user()} AND title ILIKE '%{q}%' ORDER BY id"
).fetchall()
```

You don't need an attack string to prove this. Search for the ordinary name `O'Brien`. The apostrophe ends the SQL string early, the query breaks, and the page returns an error. An honest customer has just shown that input is reaching the query's structure. `test_an_apostrophe_in_a_search_is_harmless` now fails.

@done The apostrophe test fails on this branch, and I can explain why.

## Step 9: Add an output flaw, and prove it harmlessly

In `app/templates/note.html`, change `{{ body }}` to `{{ body|safe }}`. The `|safe` filter tells Jinja to stop escaping.

Add a note whose body is `<b>hello</b>`, and open it. If "hello" appears in bold, the browser treated your text as HTML. Bold text is harmless, but it proves that anyone's note could change the page for its reader. `test_html_in_a_note_is_shown_as_text` now fails.

Commit all three flaws to the `vulnerable` branch, with a clear message for each. You've now got a real diff to show.

@done Three tests fail on `vulnerable`, and all pass on `main`.

## Step 11: Catch the pattern automatically

@help semgrep guided

**Semgrep** searches code for patterns that you define, as in [lesson 68](/courses/0068-threat-modeling-and-secure-sdlc/). Install it, and create `rules/app.yml`:

```bash
python3 -m pip install semgrep
```

```yaml
rules:
  - id: sql-built-with-an-f-string
    languages: [python]
    severity: ERROR
    message: Pass values as parameters, not inside the SQL text.
    pattern: $DB.execute(f"...", ...)
  - id: template-output-marked-safe
    languages: [generic]
    severity: ERROR
    message: "|safe turns off HTML escaping."
    paths:
      include: ["*.html"]
    pattern: "|safe"
```

Run it on each branch:

```bash
semgrep scan --config rules app --error
```

On `vulnerable`, it reports the f-string and the `|safe`. On `main`, it's quiet. Notice what it **doesn't** find: the missing ownership check, since there's no pattern for code that isn't there. That's why you need both tools and people.

@done Semgrep finds two of my three flaws, and I can explain why it misses the third.
