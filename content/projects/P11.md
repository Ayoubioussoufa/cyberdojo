## Step 2: Hash, then work on copies

@goal If you must acquire evidence, make an image with FTK Imager to external storage. Hash everything into `evidence.sha256` before you touch it, start a chain-of-custody table, and work only on copies.
@search ftk imager create disk image | chain of custody template digital forensics | sha256sum -c verify

If you have to acquire the evidence yourself, use **FTK Imager**.

@help ftk-imager guided

Download it from [exterro.com](https://www.exterro.com/digital-forensics-software/ftk-imager). On the machine, choose **File → Create Disk Image**, pick the source, and save to external storage as E01. It records hashes for you. For a VM, you can use a copy of its disk file.

Either way, hash what you have, before you do anything else:

```bash
sha256sum evidence/* | tee evidence.sha256
```

Later, `sha256sum -c evidence.sha256` proves that nothing changed. Start your chain-of-custody table, as in [lesson 59](/courses/0059-incident-response/). Work only on copies.

@done My hashes are recorded, and my custody table is started.

## Step 3: Collect and parse artifacts

@goal Collect artifacts with KAPE, parse them with Eric Zimmerman's tools, and answer in order: what ran, what survives a reboot, who logged on, and what files changed. Give a source for every answer.
@search kape targets modules tutorial | prefetch amcache forensic meaning | mftecmd timeline explorer

@help kape guided

**KAPE** collects and processes the most useful artifacts. Get it from [Kroll](https://www.kroll.com/en/services/cyber/incident-response-recovery/kroll-artifact-parser-and-extractor-kape). Its interface, `gkape.exe`, lets you choose a source, a target such as `KapeTriage`, and a destination. Run it against a mounted copy of the evidence.

@help ez-tools guided

**Eric Zimmerman's tools** parse those artifacts into CSV files. Get them from [his site](https://ericzimmerman.github.io/), where one script downloads them all. On Windows:

```powershell
.\PECmd.exe -d C:\case\Prefetch --csv C:\case\out
.\AmcacheParser.exe -f C:\case\Amcache.hve --csv C:\case\out
.\MFTECmd.exe -f C:\case\$MFT --csv C:\case\out
```

Open the results in **Timeline Explorer**, from the same site. Answer these in order, using the table in [lesson 65](/courses/0065-forensic-principles/):

| Question | Look at |
|---|---|
| What ran? | Prefetch, Amcache |
| What survives a reboot? | Run keys, services, scheduled tasks |
| Who logged on? | Event logs: 4624, 4672 |
| What files changed? | `$MFT` |

@done I've got a list of suspicious programs and logons, each with its source.

## Step 4: Analyse the memory

@goal Use Volatility 3 to save the process tree, command lines, network connections and `malfind` output. Point to a suspicious process, and explain why, with evidence.
@search volatility 3 windows plugins | windows process tree normal parent | malfind false positives

@help volatility guided

**Volatility 3** reads a memory image. Windows symbols download automatically.

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install volatility3
vol -f memory.dmp windows.info
```

If `windows.info` prints the system's details, it's working. Then go through these, and save each one:

```bash
vol -f memory.dmp windows.pstree > pstree.txt
vol -f memory.dmp windows.cmdline > cmdline.txt
vol -f memory.dmp windows.netscan > netscan.txt
vol -f memory.dmp windows.malfind > malfind.txt
```

Look for a process with the wrong parent, a command line that makes no sense, and connections from things that shouldn't connect. `malfind` gives leads, not verdicts, as you learned.

@done I can point to a suspicious process, and explain why, with evidence.

## Step 5: Build the timeline

@goal Build a timeline with Plaso, narrow it to the hours around your first suspicious event, and keep your own short timeline in UTC. Each row needs a source, with facts and inferences in separate columns.
@search log2timeline psort tutorial | forensic timeline analysis

@help plaso guided

**Plaso** pulls timestamps from many sources into one timeline. Use its Docker image, with your evidence in `/data`:

```bash
docker pull log2timeline/plaso
docker run -v /data/:/data log2timeline/plaso log2timeline --storage-file /data/evidences.plaso /data/evidences
docker run -v /data/:/data log2timeline/plaso psort -w /data/timeline.log /data/evidences.plaso
```

The output is huge, so narrow it to the hours around your first suspicious event. Keep your own short timeline of the events that matter, in UTC, with the source of each.

| Time (UTC) | Source | Fact | Inference |
|---|---|---|---|
| 03:14:02 | Security log 4624 | `svc_web` logged on, type 3 | Probably a stolen password |

Keep the two columns apart. [Lesson 65](/courses/0065-forensic-principles/) has a drill for this.

@done My timeline has a source for each row, with facts and inferences kept apart.
