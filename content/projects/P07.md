Testers are hired for their reports, not their tools. This project is about the whole engagement: the paperwork, the method, the evidence, the prioritising and the retest.

This course doesn't teach attack techniques. For the hands-on exploitation that the roadmap asks for, use a platform built for it, such as [TryHackMe's Jr Penetration Tester path](https://tryhackme.com/) or [Hack The Box Academy](https://academy.hackthebox.com/). Practise there, then come back to apply the method here, on your own lab only.

## Step 2: Enumerate, and keep notes

@goal Scan every host in your scope for all open ports and service versions, saving the output to files. Keep a dated log of each command and finding in `notes.md`.
@search nmap all ports service version | nmap output formats

@help nmap recall

**Your task:** scan every host in your scope. Find all open ports and their service versions, and save the output to files. You did this in P01.

@reveal Show me the commands
```bash
nmap -sV -p- -oA scans/dc1 192.168.1.10
nmap -sV -p- -oA scans/ws1 192.168.1.20
nmap -sV -p- -oA scans/srv1 10.10.20.10
```
`-p-` scans every port, and `-oA` saves in all formats.
@endreveal

Keep a dated log of each command and each thing you notice in `notes.md`, as you go. Those notes become your report, and you can't rebuild them afterwards.

@done I have scan files for every host, and timestamped notes.

## Step 3: Run a vulnerability scanner

@goal Install Nessus Essentials on Kali, and run a scan of every host in scope. Use credentials if you can, because they give far better results.
@search nessus essentials install kali | nessus credentialed scan

@help nessus guided

**Nessus Essentials** is a free scanner for up to 16 addresses. Register at [tenable.com/products/nessus/nessus-essentials](https://www.tenable.com/products/nessus/nessus-essentials) to get an activation code. Download the Debian package, then:

```bash
sudo dpkg -i Nessus-*.deb
sudo systemctl start nessusd
```

Open `https://localhost:8834` on Kali, finish the setup, and let it download its plugins, which takes a while. Create a **Basic Network Scan** with your scope's addresses. For much better results, add a **credentialed** scan with a lab account, so that it can look from inside each machine.

@done I've got a finished scan report for every host in my scope.

## Step 7: Write the report

@goal Write a 10 to 20 page report for managers and engineers: one-page executive summary, scope and method, attack path, findings, strategic recommendations and appendix. Have someone read the summary, and export it as a PDF.
@search penetration test report structure | executive summary security report example

Write 10 to 20 pages, for two kinds of reader, using [lesson 50](/courses/0050-spotting-attacks-and-writing-findings/) for each finding.

| Section | For |
|---|---|
| Executive summary, one page, no jargon | Managers |
| Scope and method | Auditors |
| Attack path | Everyone |
| Findings: impact, steps, evidence, severity, fix | Engineers |
| Strategic recommendations | Managers |
| Appendix: scans and notes | Whoever checks your work |

Have someone else read the executive summary. If they can't tell you what to do first, rewrite it. Export it as a PDF.
