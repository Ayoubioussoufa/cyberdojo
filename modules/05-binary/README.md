## Modules

### Foundation

- [Reading x86-64 assembly](01-x86-64-assembly.md): The language your CPU actually runs. Registers, the stack, calling conventions and how C turns into instructions, taught for reading, because defenders need to read far more than write.
- [Executables and linking](02-executables-and-linking.md): What's inside an ELF or PE file, how a process is laid out in memory, and how the GOT and PLT let programs share libraries. The map behind binary security.

### Intermediate

- [Stack memory safety](03-stack-memory-corruption.md): Why writing past a buffer matters. Stack overflows as a coding bug, how they appear in review, and what a canary and a sanitizer do when you trigger one on your own code.
- [Exploit mitigations](06-exploit-mitigations.md): The compiler, OS and hardware defences that make memory bugs harder to abuse. ASLR, NX, canaries, RELRO, CFI, shadow stacks and memory tagging, and how to verify a binary has them.
- [Static reverse engineering](07-static-reverse-engineering.md): Understanding a program without running it. A triage workflow, Ghidra and its peers, why decompiled code misleads, and how to deal with obfuscation.
- [Dynamic analysis and debugging](08-dynamic-analysis-and-debugging.md): Watching a program run. gdb, strace and ltrace, what to look for in a crash, how debuggers work, and why software sometimes tries to detect that it's being watched.
- [Fuzzing](09-fuzzing.md): Let a machine find your bugs before someone else does. How coverage-guided fuzzing works, writing a harness, running with sanitizers, and making it a routine part of your pipeline.

### Advanced

- [Heap, integer and format bugs](04-heap-and-integer-bugs.md): The other memory safety classes. Use-after-free, double free, integer overflow, format strings and type confusion, as a code reviewer sees them, and how tools catch each.
- [Assessing exploitability](05-exploitation-concepts.md): How defenders judge whether a crash is dangerous. What a primitive means, why mitigations changed the economics, and how to triage a memory bug without writing an exploit.
- [Program analysis and the kernel](10-symbolic-execution-and-kernels.md): Finding bugs by reasoning about code. Symbolic execution and its limits, static analysis at scale, why the kernel is such a critical surface, and how it's being hardened.
